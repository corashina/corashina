## Architecture

- `assets/hero.svg` and `assets/link-*.svg` are generated by `scripts/build-art.mjs` and committed. They embed subset Sora and Inter fonts (OFL, in `fonts/`) as base64 woff2, and animate with CSS keyframes and SMIL, which GitHub renders inside `<img>`.
- `scripts/build-cards.mjs` fetches public data from the GitHub API with the workflow token and writes `languages.svg` (top 6 languages by bytes across non-fork repos) and `activity.svg` (daily contributions for the last 30 days).
- `.github/workflows/profile.yml` runs daily, on push to main and by hand. It builds the two cards, runs `Platane/snk` for the eel, and publishes all three to the `output` branch. The README loads them from `raw.githubusercontent.com/.../output/`.
- No npm dependencies. Node 20+.

## Error handling

- If an API call fails, the card script exits non-zero and the previous files on `output` stay in place, so the README never shows a broken image after the first successful run.
- Card rendering escapes all text pulled from the API.

## Testing

- `node scripts/build-art.mjs` must produce valid SVG; checked by parsing every asset with a strict XML parse in `scripts/check.mjs`.
- `node scripts/build-cards.mjs --sample` renders the cards from built-in sample data so they can be checked without a token.
- Visual check: render README pieces in Chromium and look at them at desktop and phone width.
